# EPIC-02 — Input & Data Layer (brief steps 1–3)

**Objective:** Excel competitor ingestion with validation, and the pluggable
`DataSource` layer that produces company profiles and historical posts for a
configurable analysis period.

## Scope

**In:** Excel ingest + validation report, competitor persistence, `DataSource` ABC,
Mock/Import/Apify/Playwright adapters, mock dataset generator, collection orchestration
(`collect` stage callable standalone), sample input workbook.
**Out:** any classification/analysis, API routes beyond upload/collect triggers
(minimal versions allowed), frontend.

## Interfaces & contracts

### Excel input (`src/app/input/excel.py`)

Columns (case-insensitive, order-free): `Competitor, LinkedIn URL, Industry,
Country/Market, Priority`. Dynamic row count. Per-row validation:
- LinkedIn URL must match `https?://(www.)?linkedin.com/company/<slug>` (normalize to
  canonical https form; reject profile/school URLs with a specific error).
- Priority ∈ {High, Medium, Low} (case-insensitive, default Medium if blank + warning).
- Missing name or URL → row rejected with reason.

Returns `IngestReport {accepted: list[CompetitorIn], rejected: list[RowError],
warnings}`; accepted rows upsert into `competitors` (unique on canonical URL).
Ship `data/input/competitors_template.xlsx` + `data/input/sample_competitors.xlsx`
(5 realistic fictional competitors matching the brief's industries/markets).

### Schemas (`src/app/schemas/collection.py`)

```python
class CompanyProfile(BaseModel):
    name, linkedin_url, description, industry, website: str | None
    followers: int | None
    geographies: list[str]; services: list[str]
    target_audience: str | None; positioning: str | None

class RawPost(BaseModel):
    url: str; posted_at: datetime; content: str
    media_type: Literal["image","carousel","video","text","poll","article","document","unknown"]
    reactions: int | None; comments: int | None; reposts: int | None
    hashtags: list[str]   # parsed from content if not provided
```

### DataSource (`src/app/datasources/base.py`)

```python
class DataSource(ABC):
    name: str
    def fetch_company_profile(self, linkedin_url: str) -> CompanyProfile: ...
    def fetch_posts(self, linkedin_url: str, since: datetime) -> list[RawPost]: ...
```

Factory `get_datasource(name, settings)`; active adapter from config
(`app.yaml: collection.adapter`, default `mock`). Period from
`collection.period_days` ∈ {7,10,30,60,90} (validated), overridable per run.

### Adapters

- **MockAdapter** (`mock.py`): deterministic (seeded from company slug) synthetic data —
  30–60 posts/90 days per competitor with realistic format mix, topic-flavored content
  text, hashtags, engagement distributions correlated with format, follower counts
  10k–500k. Powers demo/tests.
- **ImportAdapter** (`imports.py`): reads `data/imports/<slug>/profile.json` +
  `posts.csv|json`; documented schema in `docs/import-format.md`.
- **ApifyAdapter** (`apify.py`): Apify REST API (actor IDs + token in config/env);
  maps actor output → schemas; clear error if no `APIFY_TOKEN`.
- **PlaywrightAdapter** (`playwright_adapter.py`): public company pages; **enabled only
  if** `collection.allow_scraping: true` AND `ACKNOWLEDGE_LINKEDIN_TOS=true` env var;
  otherwise raises `ScrapingDisabledError` with the compliance message. Best-effort
  selectors, rate-limited, no login flow.

### Collection stage (`src/app/datasources/collector.py`)

`collect_for_run(run_id, competitors, adapter, period_days)`:
- Upserts `company_profiles`, inserts new `posts` (dedupe on post URL), tags
  `source_adapter`, tolerates per-competitor failures (records error on run, continues).

## Acceptance criteria

1. Uploading the sample Excel returns an ingest report with 5 accepted rows; a corrupted
   fixture returns precise per-row errors without failing the request.
2. A collect run with MockAdapter on the sample competitors persists profiles + posts;
   re-running does not duplicate posts.
3. Changing `period_days` changes the date-window of collected posts (test at 7 vs 90).
4. PlaywrightAdapter raises `ScrapingDisabledError` by default; enabling requires both
   config flag and env acknowledgement.
5. One competitor's adapter failure doesn't abort the run; run record shows the error.
6. `make test` offline; `make demo` (partial: ingest + collect) completes.

## Implementation notes (2026-08-27)

- **`CompanyProfile` fields.** Spec lists `name, linkedin_url, description, industry,
  website` as `str | None`; implemented exactly so (all optional, defaulting `None`).
  `geographies` / `services` default to `[]`. The DB `company_profiles` table has no
  name/url/industry/website columns (those live on `competitors`), so `ProfileRepo`
  persists only description, followers, geographies, services, target_audience,
  positioning + `fetched_at`.
- **Hashtag normalisation.** `RawPost` lowercases and strips a leading `#` from every
  hashtag (explicit or parsed from content) so all adapters emit a consistent form.
- **Invalid (non-blank) priority** is a row rejection with a specific reason; only a
  *blank* priority defaults to Medium + warning (per spec). In-file duplicate URLs keep
  the first row and add a warning.
- **Config plumbing.** `collection.period_days` is validated against {7,10,30,60,90} by
  `resolve_period_days(override, app_config)` — per-run override wins, else config.
  Apify actor IDs / base URL / posts limit live under `collection.apify` in
  `config/app.yaml`; the token stays in `APIFY_TOKEN`.
- **`POST /api/runs` runs collection synchronously** (mock adapter is fast and this
  keeps tests simple). Solution-design's "background" execution is deferred to the
  EPIC-07 full-pipeline version of this route. A per-competitor failure yields a
  completed run whose `runs.error` accumulates the messages (criterion 5); a whole-run
  exception marks the run failed and returns 500.
- **`RunRepo.finish`** no longer clears `runs.error` when called without an error, so
  non-fatal errors recorded by `append_error` survive run completion.
- **`make demo`** replaced with the EPIC-02 ingest→collect flow (offline, no LLM). The
  EPIC-01 registry/router wiring check is dropped; it is re-exercised by unit tests.
